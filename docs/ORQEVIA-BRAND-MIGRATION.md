# ORQEVIA · 奥启维亚 brand migration

Official English brand and primary application name: **ORQEVIA**. Official Chinese brand: **奥启维亚**. This updates the existing application.

Current display copy, app metadata, response identity, control screens and artifact headings use the new name. The owner-approved original raster supplies full-image resized PNGs for the favicon, 192/512-pixel manifest icons and 180-pixel Apple touch icon. The earlier generated Q icons are retained as unapproved historical/compatibility assets. See [official source provenance and technical resizing](ORQEVIA-OFFICIAL-LOGO.md).

The app's manifest ID, scope, start URL and origin remain `/pwa/` on the existing host. Protocol/schema identifiers, API routes, cookie names, enrolled device identity, client reference database, registry IDs, service names, authentication audiences, TLS pins and historical evidence retain their compatible values. Historical JARVIS PRIME files and Golden manifests remain dated evidence. New exact runtime-status objectives are accepted alongside the historical objectives, with no broader action matching.

Shell `orqevia-shell-v20` downloads the complete public asset allowlist before activation. Activation removes only superseded `jarvis-shell-*` and `orqevia-shell-*` caches. Private API responses bypass the cache. Cookies, IndexedDB and private task/artifact data are not reset. A failed download keeps the existing worker active.

## iPhone update and acceptance

1. Keep the existing home-screen installation. With the iPhone on the trusted network, open it while online, then close and reopen it after the application refresh. Confirm **ORQEVIA · 奥启维亚**, the existing Owner role, saved task references and a working backend connection.
2. Open the same trusted URL in Safari: `https://192.168.1.23:8443/pwa/`. Refresh it and confirm the page title, branding and connection. Safari and an installed web app can have separate session/storage contexts; do not assume one proves the other.
3. In each context, use **Your connection → Verify Owner authority**, submit a small objective, open its returned result and use **Verify & save** on its artifact. Record task UUID, result/artifact digest, runtime revision and observation time. A registered agent count is not readiness or end-to-end acceptance.
4. If the old home-screen label/icon persists, keep that installation. In Safari, open the same URL, tap **Share → Add to Home Screen**, set the name to **ORQEVIA**, leave **Open as Web App** enabled if shown, then tap **Add**. Apple documents this [installation flow](https://support.apple.com/guide/iphone/iphea86e5236/ios). If Add to Home Screen is absent, use **Edit Actions** to add it.
5. Open the new shortcut and complete the Owner/session/task/artifact checks before removing any old shortcut. A new installation can need its own one-time device enrollment; preserve the original enrollment and installation until the new context is accepted. Do not clear Safari website data, revoke the old session or delete the existing installation to refresh branding.

Server and portable/browser checks do not prove physical Safari, installed-icon refresh, iPhone Owner session or touch/voice behavior. Record those separately from source and deployment receipts. The existing master ledger and coaching acceptance criteria remain in force.
