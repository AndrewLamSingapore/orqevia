# Hugging Face provider candidate (not deployed)

This source candidate adds text-only streaming chat to PRIME's existing governed cloud path. It does not activate a model or change Golden Gen2. The example catalog is disabled and unpriced. Browser login is not an API credential.

## Boundary

- The example catalog uses `file:HF_TOKEN`. PRIME resolves it only at the transport boundary from the fixed `/run/secrets/hf_token` path; agents and the PWA receive neither the token nor a token reference. The adapter fixes HTTPS to `https://router.huggingface.co/v1/chat/completions` and requires an explicit `model:provider` route, avoiding provider auto-selection. The earlier `env:HF_TOKEN` reference remains supported for existing configurations, but is not used by the example.
- The request uses Hugging Face's documented `max_tokens`, streaming and usage fields. Existing bounded retries, cost reservation, data-classification policy, action records and outcome metrics remain in the PRIME cloud path. Tools, constrained structured output, embeddings and vision are **not** advertised by this adapter.
- A Hugging Face catalog entry cannot be enabled without `qualification_status=QUALIFIED`. Qualification still requires a fresh model/provider availability and price check, cost ceiling, privacy decision, a scoped token with Inference Providers permission, an isolated real request, validation, and provenance review. An enabled entry with unknown prices is not admitted by the queue.
- A queued HF job additionally needs an explicit `preferred_provider` matching the qualified catalog entry, `allow_cloud=true`, `data_classification=CLOUD_PERMITTED`, and a positive cost ceiling. The queue excludes HF from generic cloud provider selection before a lease is issued. The executor rechecks these fields and the queued cost reservation against current catalog prices immediately before resolving the credential. HF cannot become an implicit fallback for a generic cloud job. The Owner-authenticated compute queue API accepts `preferred_provider`; its omission retains prior local-first behavior.
- A narrowly qualified HF entry may set `allowed_task_classes`, for example `["classification"]`. Admission rejects missing, unmatched or malformed task classes before resolving a credential; both the selected primary and an HF alternate must permit the queued class. A prepared fallback is denied if either bound allowlist changes, even if the new list still includes the task. Omitting this optional policy preserves existing broadly qualified catalogs; descriptive `qualification_scope` text alone is not enforcement. Task labels restrict routing, not substantive quality: a single classification canary does not qualify arbitrary prompts, general capability, an agent role matrix or L7. Production configuration must select the scope actually supported by independent evidence and include bounded default context/output/timeout budgets.
- Provider `health()` reports local credential readiness only; network health stays `UNMEASURED` until an actual request. Failures must not be reported as success or silently retried after ambiguous execution.

## Remaining acceptance

As of 4 October 2026, a dedicated fine-grained Inference Providers token was entered into an Admin-only file outside Git and one isolated, synthetic PRIME-adapter inference succeeded. The redacted local receipt is `ABEX/recovery-records/master-closure-20261004/HUGGING_FACE_REAL_INFERENCE_20261004.md`. This does not qualify the model for production, prove the 21-agent objective, establish Owner PWA behavior, rehearse Golden rollback, or authorize promotion. The example catalog remains disabled and unpriced. Never put the token in chat, Git, `.env`, shell history, the PWA or an agent environment. The parent `ABEX/private` directory has a broader inherited read ACL, so the Owner-only child is the intended storage boundary. Do not change that ACL or create the token file through this source change.

`docker-compose.huggingface.yml` is opt-in. Set `PRIME_HF_TOKEN_FILE` to the protected host file path (the path is not the credential), then include the override in the Compose invocation. It grants the file only to the `prime` service at `/run/secrets/hf_token`; the interface and other services have no HF grant. The resolver accepts only the symbolic `file:HF_TOKEN` reference, rejects arbitrary paths, symlinks, non-regular files, empty/oversized files and whitespace/control bytes, and returns generic errors without token bytes or paths. The provider remains disabled and unqualified. The isolated canary and file ACL check do not prove a production mount or govern real Owner data. Before production admission, verify current model/provider availability and price, privacy and budget, redacted provenance, and local-path comparison; respect Golden rollback and host thermal gates.
