# Hugging Face provider candidate (not deployed)

This source candidate adds text-only streaming chat to PRIME's existing governed cloud path. It does not activate a model or change Golden Gen2. The example catalog is disabled and unpriced. Browser login is not an API credential.

## Boundary

- The example catalog uses `file:HF_TOKEN`. PRIME resolves it only at the transport boundary from the fixed `/run/secrets/hf_token` path; agents and the PWA receive neither the token nor a token reference. The adapter fixes HTTPS to `https://router.huggingface.co/v1/chat/completions` and requires an explicit `model:provider` route, avoiding provider auto-selection. The earlier `env:HF_TOKEN` reference remains supported for existing configurations, but is not used by the example.
- The request uses Hugging Face's documented `max_tokens`, streaming and usage fields. Existing bounded retries, cost reservation, data-classification policy, action records and outcome metrics remain in the PRIME cloud path. Tools, constrained structured output, embeddings and vision are **not** advertised by this adapter.
- A Hugging Face catalog entry cannot be enabled without `qualification_status=QUALIFIED`. Qualification still requires a fresh model/provider availability and price check, cost ceiling, privacy decision, a scoped token with Inference Providers permission, an isolated real request, validation, and provenance review. An enabled entry with unknown prices is not admitted by the queue.
- Provider `health()` reports local credential readiness only; network health stays `UNMEASURED` until an actual request. Failures must not be reported as success or silently retried after ambiguous execution.

## Remaining acceptance

The Owner's browser sign-in does not provide `HF_TOKEN` to ABEX. No token, paid service, model inference, 21-agent HF objective, Owner PWA path, Golden rollback or production promotion has been performed. Keep the example disabled until the Owner creates a dedicated fine-grained token with **Make calls to Inference Providers** permission, then places the exact token bytes, with no trailing newline, directly in an Admin-only file below the protected `ABEX/private/prime-epoch-20260919` directory. Verify that the new file retains the Admin-only ACL. Do not put the token in chat, Git, `.env`, shell history, the PWA or another agent's environment. The parent `ABEX/private` directory has a broader inherited read ACL, so the Owner-only child is the intended storage boundary. Do not change that ACL or create the token file through this source change.

`docker-compose.huggingface.yml` is opt-in. Set `PRIME_HF_TOKEN_FILE` to the protected host file path (the path is not the credential), then include the override in the Compose invocation. It grants the file only to the `prime` service at `/run/secrets/hf_token`; the interface and other services have no HF grant. The resolver accepts only the symbolic `file:HF_TOKEN` reference, rejects arbitrary paths, symlinks, non-regular files, empty/oversized files and whitespace/control bytes, and returns generic errors without token bytes or paths. The provider remains disabled and unqualified. Validate the host ACL and container file access in an isolated test before deployment. After the Owner's privacy and cost decision, verify a non-sensitive pinned model through PRIME and compare with the existing local path before considering promotion.
