# Hugging Face provider candidate (not deployed)

This source candidate adds text-only streaming chat to PRIME's existing governed cloud path. It does not activate a model or change Golden Gen2. The example catalog is disabled and unpriced. Browser login is not an API credential.

## Boundary

- The example catalog uses `file:HF_TOKEN`. PRIME resolves it only at the transport boundary from the fixed `/run/secrets/hf_token` path; agents and the PWA receive neither the token nor a token reference. The adapter fixes HTTPS to `https://router.huggingface.co/v1/chat/completions` and requires an explicit `model:provider` route, avoiding provider auto-selection. The earlier `env:HF_TOKEN` reference remains supported for existing configurations, but is not used by the example.
- The request uses Hugging Face's documented `max_tokens`, streaming and usage fields. Existing bounded retries, cost reservation, data-classification policy, action records and outcome metrics remain in the PRIME cloud path. Tools, constrained structured output, embeddings and vision are **not** advertised by this adapter.
- A Hugging Face catalog entry cannot be enabled without `qualification_status=QUALIFIED`. Qualification still requires a fresh model/provider availability and price check, cost ceiling, privacy decision, a scoped token with Inference Providers permission, an isolated real request, validation, and provenance review. An enabled entry with unknown prices is not admitted by the queue.
- Provider `health()` reports local credential readiness only; network health stays `UNMEASURED` until an actual request. Failures must not be reported as success or silently retried after ambiguous execution.

That canary did not use the production queue or certify an agent, and its then-observed provider availability and price are not a standing qualification. No paid plan, Owner PWA path, Golden rollback or production promotion was established. Keep the example disabled. Never put the token in chat, Git, `.env`, shell history, the PWA or another agent's environment. The protected `ABEX/private/prime-epoch-20260919` child directory remains the intended storage boundary; do not change its ACL or create a token file through this source change.

`docker-compose.huggingface.yml` is opt-in. Set `PRIME_HF_TOKEN_FILE` to the protected host file path (the path is not the credential), then include the override in the Compose invocation. It grants the file only to the `prime` service at `/run/secrets/hf_token`; the interface and other services have no HF grant. The resolver accepts only the symbolic `file:HF_TOKEN` reference, rejects arbitrary paths, symlinks, non-regular files, empty/oversized files and whitespace/control bytes, and returns generic errors without token bytes or paths. The provider remains disabled and unqualified. Before any production admission, verify current pinned model/provider availability, price, privacy and budget; run a bounded synthetic queue-to-provider request with redacted provenance; compare with the local path; and respect Golden rollback and host thermal gates.
