# Command Center observation repair, 7 November 2026

This change addresses verified source defects; this document is not a deployment
or physical-device receipt. Runtime evidence is retained separately by the owner.

The host sampler is a protected one-minute Windows SYSTEM task. It publishes
same-host, same-boot receipts through a read-only interface mount. A fresh sampler
does not establish that every probe, incident store or agent execution is known.
The screenshot's stale receipt describes an earlier observation, not current
service state.

The operational collector accepted only an obsolete shared-container OTEL network
layout and classified the intelligence route's expected unauthenticated HTTPS401
as a service failure. It now accepts the actual common Docker network only with
current container identities, start times and recent nonempty telemetry exports.
The intelligence probe reports only the verified HTTPS authentication boundary;
the service still requires its separate authenticated Docker healthcheck.

Canary validation now includes the seventeenth disaster-recovery observation,
checks internally consistent UNKNOWN/PAUSED summaries, and rejects observations
from before the current boot. Core service functionality remains separate from
broader verification coverage. An authoritative critical count requires every
declared critical observation and an observed, conflict-free incident journal.
Missing evidence remains unavailable. Reconciliation preserves recovered incident
records and transitions; response limits do not delete stored history.

checks and collector provenance before displaying healthy states or a current
critical count. It renders diagnostic reasons, timestamps and separate broader
coverage. Malformed rows and stale receipts cannot produce authoritative zero.
Registered agents and evidence-backed execution counts remain distinct.
