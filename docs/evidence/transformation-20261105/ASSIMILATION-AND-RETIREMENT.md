# Implemented NOMAD assimilation and frontend retirement

## Implemented in the shared batch source

1. Replaced the old layered tactical/sovereign dashboards with one ivory/olive
   Command Center, original geometric branding, direct capability navigation
   and a mission draft shortcut.
2. Moved existing mission, agent, learning, document, geographic, operational
   and recovery handlers into the canonical replacement surfaces. Their IDs,
   server session/CSRF transport, owned-task binding, artifact integrity and
   continuation behavior remain functional contracts.
3. Added a native Supply Depot presentation over the parent's fixed authenticated
   manifest endpoint. Source installation, runtime availability and qualification
   are distinct; supported capability links open existing tools.
4. Added an audited, read-only wallet view. It does not create an account, expose
   keys, sign transactions, infer funds from accounting, or grant spending rights.
5. Added the parent's fixed evolution experiment and saved-run metadata endpoints
   to the Evolution page. No browser-supplied code, score criteria or permissions
   are accepted. Synthetic held-out evidence is labelled by its actual scope.
6. Preserved the old Control/Evidence Lens functions through the parent's
   authenticated same-origin bridge: read task, explicitly record evidence, and
   inspect stored integrity/currentness. Discovery never records evidence.
7. Applied the same design to public pages, projects/notebooks, cache repair,
   maps, dialogs, forms, tables, logs and mobile navigation.

## Adapted, retained and rejected

- **Adapted:** NOMAD's concise dashboard, installed-service catalog, honest
  dependency/version/resource display, local content visibility and task docs.
- **Retained:** Orqevia's existing local/cloud providers, retrieval/FAISS memory,
  21 capability inventory, PIF/MEL/Fabric, Academy, Resource Guardian, durable
  missions, security boundaries and deployment/recovery pathway.
- **Rejected for this batch:** wholesale Adonis/React/Inertia/MySQL/Redis/BullMQ
  adoption, an extra vector database, unauthenticated LAN trust, direct browser
  Docker authority, mutable/latest unattended updates, duplicated notes/files,
  automatic Kiwix/content/media installations, and NOMAD branding.
- **Deferred pending evidence:** useful mission-specific ZIM packs, PMTiles,
  CyberChef/other utilities and service lifecycle automation. Their presence in
  NOMAD is not evidence that Orqevia needs another persistent service.

The current Supply Depot is a discovery/use surface, not a completed generic
installer. Install/update/remove/rollback use the existing host release pathway.
No fake lifecycle controls or arbitrary shell execution are presented. This
limitation is explicit in the product and reconnaissance report.

## Retired active frontend behavior

- Removed the old navigation hierarchy and governance-oriented dashboard as an
  operating experience; model/memory, action permissions and evidence functions
  remain directly available where useful.
- Removed the competing dark/light/tactical theme and visual overlay stack.
- Replaced the public governance-orbit illustration and authority-first prose
  with the same direct capability identity as the private application.
- Canonicalized legacy view queries so they render the replacement interface.
- Updated the service-worker release/allowlist and manifest/install icons;
  private API responses remain outside offline caches.

No data, models, task histories, wallet controls, source evidence or rollback
artifacts were deleted. The original frontend is preserved in the dated
`frontend-before` evidence directory with a SHA256 manifest. Parent owns server
retirement of `/control` and `/orqevia` legacy HTML routes, backend PRIME
dependencies, deployment and live runtime verification; this report does not
claim those actions from frontend source changes alone.

## License and supply-chain scope

NOMAD's inspected application license is Apache-2.0. `DEPENDENCY-LICENSES.json`
preserves direct upstream license observations for Tabler, Ollama, Qdrant,
Kiwix, MapLibre, CyberChef and Tailwind. Those license files were inspected from
their default branches and pinned by blob SHA, not asserted to be a complete
version-specific/transitive audit. No new application package was introduced.
Existing lockfiles and existing vendor notices are retained. Upstream source
snapshots in this evidence folder retain the upstream license; active code is a
native adaptation and ships no NOMAD mark or copied frontend stack.
