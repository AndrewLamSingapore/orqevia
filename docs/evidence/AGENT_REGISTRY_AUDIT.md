# Agent registry audit method and interpretation — 2026-10-02

The JSON companion is a read-only projection, not an execution proof. I parsed `config/agent_registry.json`, checked its SHA-256 against `/app/config/agent_registry.json` in the live PRIME container (both `fec92b1d0e3e858bc5f4fe1b26401d053ee94b9b2358be8da379b97884d916ff`), and inspected only the live `PRIME_REGISTRY_V1_ENABLED=1` flag. No prompts, credentials, job payloads, or agent outputs were accessed. I inspected `app/agent_registry.py`, `app/agent_dispatch_api.py`, `app/compute_queue_api.py`, `app/spine.py`, `app/engineering_api.py`, and `app/artifact_delivery.py` in the isolated worktree. No agent job or model request was dispatched.

The frozen registry has 21 unique registered agents, six leads, and 29 uniquely owned responsibility IDs. Each record declares input/output contracts, capability ownership, model-tier eligibility, tool eligibility, fallback, and observability fields. `app/agent_registry.py` enforces uniqueness, parent/child delegation boundaries, responsibility coverage, advisory/restricted authority, and `model='unassigned'`. It deliberately publishes `runtime_activation_verified: false`. The JSON audit includes only public-safe identity/contract fields; it excludes internal prompts, endpoints, and credential material.

`app/agent_dispatch_api.py` maps a requested responsibility to one registered owner, applies authorization and tier routing, then enqueues advisory inference through the shared compute queue. Tool effects are separate action records. Tool eligibility is **not** evidence of executed tool use. `app/compute_queue_api.py` sets global and per-agent concurrency to one regardless of 21 registered identities. `app/spine.py` lists narrow eligible tool sinks (`artifact.create` for a09; `sandbox.wasm.execute` for a17/a18), while execution still requires the respective independent harness/authorization contracts. The registry does not establish 21 independently running processes, 21 dedicated models, or simultaneous 21-agent throughput.

This audit verifies configuration and code routing only. It does not mark the agent product fully verified or replace per-role outcome tests. A later controlled proof would need representative owned-responsibility dispatches, input/output contract checks, authority denial tests, tool-effect receipts where eligible, latency/resource measurement, and persistence/recovery checks, while respecting the one-slot host envelope. No 21-job load test was performed on the unstable host.
