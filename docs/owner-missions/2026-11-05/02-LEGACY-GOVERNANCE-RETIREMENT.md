# ORQEVIA — COMPLETE LEGACY GOVERNANCE RETIREMENT MISSION

## Mission

Permanently retire the obsolete PRIME/JARVIS governance architecture throughout ORQEVIA.

This is a fundamental architectural transformation, not a rebranding, policy rewrite or cosmetic cleanup.

ORQEVIA is now the sole intelligence operating system. PRIME survives only as historical context where necessary.

The objective is to maximize useful intelligence, autonomy, learning, adaptability, execution throughput and resource efficiency while minimizing unnecessary queues, checks, approval barriers, organizational hierarchy and procedural overhead.

## 1. Establish the actual baseline

Inspect the latest canonical GitHub `main` branch and the actual ABEX runtime.

Inventory every governance-related dependency across:

- Source code and runtime execution paths
- Agent orchestration and registries
- Model routing and inference scheduling
- Objective management and task execution
- Approval and authorization systems
- Release, deployment and rollback mechanisms
- Memory, learning, Academy and evaluation systems
- Tool execution and external integrations
- Databases, manifests, configuration and environment variables
- Frontend, APIs and mobile interfaces
- Tests, CI, documentation and operational scripts

Trace dependencies and actual behavior. Do not assume that a file's name accurately describes its function.

Classify each mechanism as obsolete bureaucracy, necessary technical protection, useful intelligence capability, historical evidence or redundant implementation.

## 2. Retire legacy governance completely

Identify and eliminate PRIME-era procedural authority structures, duplicated control planes, obsolete approval workflows, unnecessary execution gates and governance-specific orchestration dependencies.

Inspect particularly:

- `governance/`
- `app/routing_policy.py`
- `app/host_guard.py`
- `app/release_gate.py`
- `app/agent_registry.py`
- `governance/operational-manifest.json`
- `governance/CHANNEL_CONTRACT.md`
- Legacy references in `AGENTS.md`, `PLAN.md`, `README.md` and runtime documentation

These are investigation targets, not instructions to delete files blindly.

Preserve or migrate useful functionality before retiring its obsolete wrapper.

No retired governance subsystem may remain as a hidden mandatory dependency.

## 3. Replace bureaucracy with native intelligence

Use existing ORQEVIA capabilities wherever possible.

The system should dynamically:

- Understand objectives and decompose work.
- Select the most appropriate agent capabilities and models.
- Coordinate independent tasks concurrently when resources permit.
- Adapt reasoning depth to task complexity.
- Reuse memory, evidence and successful methods.
- Detect errors and recover intelligently.
- Evaluate outcomes against measurable objectives.
- Improve its methods through validated experiments.
- Allocate resources according to measured demand and benefit.

Avoid creating another permanent coordinator hierarchy, governance service, approval committee or mandatory queue.

Retain one coherent logical coordination capability, but allow its implementation to evolve.

## 4. Eliminate unnecessary execution friction

Audit every mandatory wait, approval, retry, queue, polling cycle, timeout, admission rule and blocking dependency.

For each, determine whether it is essential to correctness, security, external service limits or resource stability.

Remove unnecessary barriers.

Optimize necessary mechanisms rather than bypassing them.

Preserve fair scheduling, cancellation, bounded resource consumption and prevention of duplicate consequential actions.

Do not equate unlimited parallelism with higher intelligence or throughput.

## 5. Preserve essential technical boundaries

Retain:

- Authentication and authorization
- Tenant and user isolation
- Secret protection
- Wallet key isolation and transaction authorization
- Spending and transaction limits
- Protection against prompt-injection-driven tool misuse
- Data integrity
- Reproducible testing
- Rollback and recovery
- Minimal, reliable execution records

Implement these as narrowly scoped technical controls.

Autonomous agents must not grant themselves permissions, alter their own financial limits, disable security protections or bypass authorization for consequential external actions.

Routine low-risk work should execute without unnecessary human approval.

## 6. Transform deployment and release

Replace procedural release bureaucracy with automated, risk-proportionate verification.

Routine reversible changes should follow tested deployment pathways.

High-impact or irreversible changes require appropriate authorization and recoverability.

Preserve existing working services and production data.

Do not restart, delete, migrate or deploy consequential changes without establishing their effects and obtaining the necessary authorization.

## 7. Preserve valuable existing intelligence assets

Do not destroy working components simply because they originated during the PRIME era.

Retain and evolve:

- The 21-agent capability network
- Cognitive orchestration
- Hyper-Inference Fabric
- Predictive Intelligence Fabric
- Model Efficiency Layer
- Agent Academy
- Persistent memory and retrieval
- Resource Guardian
- Operational telemetry
- Existing provider integrations
- Desktop and mobile interfaces

Reassess every component based on actual usefulness, not historical architectural status.

## 8. Remove obsolete terminology and dependencies

After functional migration and verification:

- Remove obsolete governance interfaces and unused code.
- Retire redundant configuration and schemas.
- Update imports, tests, documentation and API contracts.
- Remove misleading PRIME authority references from active system descriptions.
- Preserve historical evidence and provenance where needed.
- Ensure no old approval mechanism silently blocks execution.

Do not rename old governance into a new governance framework.

## 9. Validate the transformation

Demonstrate:

1. Existing authorized tasks still execute.
2. The 21 logical agents remain available.
3. Model selection and inference continue functioning.
4. Learning, memory and evaluation remain intact.
5. Resource protection continues operating.
6. Wallet and external-action boundaries remain enforceable.
7. The interface remains functional on desktop and mobile.
8. Deployment and recovery paths remain viable.
9. No obsolete governance dependency remains in active execution.
10. Measured execution friction decreases without unacceptable reliability or security regression.

Separate source verification from live runtime verification.

Do not claim capabilities or improvements that have not been measured.

## 10. Deliverables

Produce:

- Complete legacy-governance dependency inventory
- Retirement and migration map
- New ORQEVIA-native execution architecture
- Implemented source changes
- Updated tests and configuration
- Performance and reliability comparison
- Security-boundary verification
- Remaining limitations and migration risks
- Exact deployment and rollback instructions

Execute independently wherever existing permissions allow.

Do not stop for procedural approvals on ordinary analysis, coding, testing or other authorized reversible work.

Do not invent a replacement governance organization.

## Final directive

ORQEVIA must become a continuously evolving intelligence operating system—not a bureaucracy that manages intelligence.

Preserve intelligence, eliminate unnecessary friction, and keep only those technical boundaries essential to safe, reliable and authorized operation.

The transformation is complete only when obsolete governance has disappeared from actual runtime behavior, not merely from documentation.
