# Shared channel reading contract

ORQEVIA component reference: https://github.com/AndrewLamSingapore/orqevia/blob/main/governance/operational-manifest.json

Lam's 15 September 2026 instruction requires ChatGPT, Codex, Sol, Astra, ABEX
and Dell to reconcile the same evidence. ORQEVIA owns shared orchestration and
cross-product contracts; each product repository owns its own source,
configuration, contracts and domain records. STATUS.md records portfolio
status claims. The operational manifest provides dated ORQEVIA component and
observation references; neither this contract nor that manifest establishes
current deployment status.

1. Resolve ORQEVIA `main` once and pin that commit for shared ORQEVIA references.
   Read the operational manifest, ORQEVIA product manifest and architecture
   references at that commit. Resolve each relevant product's owning repository
   separately; do not mix files from different commits or rely on chat memory.
2. The operational manifest records ORQEVIA architecture references and dated
   observations; `system.manifest.json` binds ORQEVIA components. STATUS.md
   records portfolio status claims and their evidence classification. No
   parallel portfolio status pointer is maintained.
3. Dell, ABEX and the Owner form one shared ORQEVIA operating authority: each
   may branch, commit, open and merge pull requests, and each may deploy or
   operate ORQEVIA where it holds actual host access and credentials. The
   fail-closed runtime gates (Stable Spine, Action Harness, host guard, FAILSAFE
   and the WASM sandbox) are unchanged by this amendment, and only the Owner
   moves items into STATUS.md "Verified" sections. PWA and voice use the same
   Interface contract. Client identity never increases authority. Earlier
   development/synchronization assignments are retained in Git history and
   superseded by the Owner's recovery directive.
4. Discover actual identities and permissions from current source and runtime
   evidence. The historical 21-agent programme is parked; its preserved registry
   and role mappings do not establish an active governing requirement, current
   execution permission, live worker count or certification.
5. Ordinary bounded work executes directly with observation and evidence;
   universal TAP/Harness pre-approval is superseded. Authentication, ownership,
   resource limits and narrow consequential controls remain. Logging is not a
   routine approval gate. Existing user authorization must be respected.
6. Git defines intended source, runtime receipts define deployment, and retained
   independent evidence proves correspondence. Never upgrade UNKNOWN, STALE,
   DISPUTED or a scoped test PASS into general production acceptance.
7. Report the relevant owning source revisions, scope verified and unresolved
   differences. Source identity and operational freshness are different fields.
   All channels must preserve that distinction and dated outstanding priorities.
8. Make changes through each owning repository's source and controls. Regenerate
   the ORQEVIA resume mirror when its input manifest changes. Older exports,
   installers and architecture documents remain historical evidence.

Domain data remains with its system of record: VELYQUA owns aquarium observations,
Portal owns its artifacts/relay records, and the other applications own their
product data. Cross-product reconciliation does not move databases into Git.

Old conversations and model memories cannot be remotely rewritten by this file.
Conformance requires a channel to read each relevant owning source; lack of access must be
reported, never presented as successful synchronization.
