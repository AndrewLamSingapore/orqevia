# Dell independent verification peer

Owner mandate: Lam, 27 September 2026. ABEX is the sole production authority. STATUS.md remains the existing portfolio status authority; this peer does not reactivate a retired truth reconciler or create a competing status source.

## Independence

ABEX owns engineering, candidate generation, controlled repair, immutable images, governed promotion, production runtime and rollback execution. Dell owns independent acquisition, adversarial challenges, regressions, evidence preservation, pre-promotion review, post-promotion audit and recovery readiness.

Dell has no production write credential, deployment token, production database mount, writable production share or unrestricted ABEX shell. Tests use disposable local fixtures, synthetic identities and bounded resources. Never execute arbitrary manifest commands. Review and pin the verifier, test commands and dependency inputs separately. DeepSeek output is advisory model content: it cannot create authority, sign receipts, establish observed facts or issue promotion verdicts.

ABEX may read published evidence but may not replace Dell records or issue Dell attestations. Shared Git hosting alone does not enforce independence: repository administrators can change branches. Positive certification needs separately controlled verifier credentials and independently retained evidence. This toolkit does not establish that trust root or claim a tamper-proof filesystem.

If Dell participates in a product repair, record the independence conflict. ABEX publishes a successor, and an independent review path verifies it. Never certify Dell's own repair as independently produced. The initial audited candidate remains unchanged.

## Intake and testing

1. Obtain an authenticated frozen publication: repository, full source commit, Git tree, freeze receipt digest, scope, build/dependency inputs, canonical commands, exact image platform/digest, migration plan and rollback identity. Mutable branch or tag names alone are insufficient. A branch-head observation is not a frozen release.
2. Fetch the exact source into a fresh detached checkout. Disable hooks and unintended filters; verify objects, tree, modes, content, submodules/LFS where present, and clean worktree. Preserve conflicting or changed observations.
3. Bind the receipt to this source and supporting evidence. A later evidence commit may bind an earlier source commit; do not require an impossible self-referential hash. Historical receipts cannot be silently rebound to a successor.
4. Review test commands, then run canonical regressions in a disposable environment without ABEX credentials or production access. Capture command, exit code, full output, times, dependency versions, inventory/skips and before/after integrity. Unavailable dependencies, isolation, history, image or service prerequisites are BLOCKED.
5. Run independently designed challenges. Every required category has test IDs and evidence, or is explicitly BLOCKED/UNPROVEN. Missing required coverage blocks promotion. Reverify successors from fresh source and fixtures.

## Evidence labels

| Label | Meaning |
|---|---|
| PROVEN_BY_AUTOMATION | A specified machine-observable assertion passed under stated conditions. |
| PROVEN_BY_INDEPENDENT_DELL | Native independent Dell execution and evidence are established; a cloud session opened from Dell is insufficient. |
| REQUIRES_PHYSICAL_DEVICE | Actual hardware/user-observable acceptance remains. |
| REQUIRES_LONGER_OBSERVATION | Required time horizon has not elapsed. |
| UNPROVEN | Adequate evidence is absent. |

Each PASS names its assertion and scope. No test total establishes broad reliability, security, audible speech or production readiness. Preserve original FAIL inputs/output under new run IDs; never replace failure with later success. Record SHA-256 manifests and retain their digest independently. Hashes detect changes relative to a trusted reference, but do not authenticate a producer. Redacted shareable exports are separate artifacts, not byte-identical originals.

Any genuine P0/P1/P2 returns FAIL with exact source, minimal deterministic reproduction where possible, expected/actual behavior, impact, logs, artifacts and digests. ABEX produces the successor. Preserve physical Owner observations even without a software reproduction. Every incident gets root cause, regression when feasible, ABEX qualification inclusion and independent challenge inclusion.

## Promotion and deployment

PROMOTION_VERIFICATION_PASS requires exact frozen source; independent Dell canonical and adversarial passes; zero unresolved P0/P1/P2; migration/rollback rehearsals; authority, provenance, identity and evidence integrity; and explicit remaining physical/observation/unproven gates. It does not authorize deployment or close Owner physical acceptance. Imported JSON or model claims cannot grant it. The supplied offline CLI deliberately cannot issue positive certification from imported claims.

After an authorized ABEX promotion, independently obtain an authenticated host-bound receipt and compare:

```
DEPLOYED_IMAGE == APPROVED_IMAGE
DEPLOYED_SOURCE == APPROVED_SOURCE
RUNTIME_REVISION == APPROVED_REVISION
```

Compare like digest types: OCI index, platform manifest and local image/config digest are distinct. Record their relationship. Tags and self-reported runtime strings are insufficient. Read health, existing task receipts, identity/session state, data preservation, provenance, drift and retained rollback artifacts. Under the current no-production-mutation instruction, Dell does not create production test tasks; it reads existing receipts or ABEX runs an authorized probe. Missing identity is BLOCKED; established mismatch is FAIL even with green health. Dell reports; ABEX rolls back.

## Read Aloud regression lesson

Capture one immutable attempt ID across gesture, API invocation, voices queried/resolved, utterance creation, start and terminal end/error/timeout/cancellation. Old callbacks cannot change a new attempt. Synchronous callbacks, rapid stop/start, missing voices, thrown API calls and missing terminal events must converge to bounded truthful state. Requested language is not proof of resolved voice. Browser start/end events are software lifecycle evidence only.

Only Owner observation can close audible physical output. Bind it to device, browser/PWA mode and deployed source/image. Relevant acceptance covers real tap, audible English/Chinese, Stop/replay, interruptions, offline/reconnect and cache/version changes. No automated stub or simulated browser proves iPhone speaker output.
