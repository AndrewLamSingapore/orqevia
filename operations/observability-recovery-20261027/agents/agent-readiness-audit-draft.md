## Algorithm and dependency findings

- `app/interface_telemetry.py:107` selected MAX(rowid), so a later transition on an older job could be hidden. It used updated_at as "heartbeat" and counted failed/cancelled latest rows as ready when recent and tags present.
- The original one-hour activity window was 3600 seconds. An observation must carry an explicit timezone and cannot be renewed by a dashboard poll. No age extension is proposed.
- All 21 source roles have lifecycle active, model unassigned, no dedicated model, and the same shared compute requirement. Registered responsibilities and declared tools are source capability contracts, not activation or competence evidence.
- Actual dispatch requires the registry dispatch flag, a valid registered capability, available routing for the requested model tier, and a current shared execution path. On this deployment the mode is direct, one Ollama inference is configured, and local tiers are NANO and MINI. A FLAGSHIP operation has no local eligible backend; that affects that operation only.
- The observed current controller heartbeat belongs to the coaching controller. Real probability-foundations.v1 failures remain in the DB. The current b360 role cohort runs before the enabled probability v2 cohort because the scheduler creates role first and permits only one active cohort. In-progress v1 work was source-superseded after its original job settled.
- Coaching outcome FAIL with a compute status completed is an executed but incorrect assessment response. Neither outcome is role liveness or certification.
